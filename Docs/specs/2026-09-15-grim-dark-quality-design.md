# 暗黑风格表现提升 — 设计

**目标：** 将原型的外观和手感提升为暗黑幻想动作游戏：重甲骑士对抗庞大巨兽、沉重而有节奏的战斗、破败的哥特式石建筑。Windows 是画质基准；WebGL 演示保留同样的角色、动画和手感，使用较轻量的特效。

**已确认的方案：** 先角色，再手感。真实角色和动画决定时序与轮廓，在它们之前进行的调整很可能需要重做。

本文列出的设计目标不等于全部已实现；任务状态见 `Docs/plans/2026-09-15-grim-dark-quality.md`，实际完成情况仍需结合源码和验证确认。

## 1. 角色和动画管线

- **来源：Mixamo，需自行获取授权资源。** 骑士使用 *Paladin J Nordstrom* 和 *Sword and Shield* 动画包；Boss 使用 *Warrok W Kurniawan* 和 *Great Sword* 动画包，是持巨大双手刀刃的巨兽。共享动画为 *Stunned*、*Getting Up*、*Falling Back Death*、*Flying Back Death*。*Mutant Pack* 可作为 Boss 大剑动画集的替换候选，接入前需检查授权和动画兼容性。
- **位置：** `Assets/_Project/Art/Licensed/Mixamo/{Characters,Animations/Knight,Animations/Boss,Animations/Shared}`，由 Git 忽略。Mixamo 资源可用于游戏和构建，不能重新分发原始资源文件。获取方式见 `Docs/ART_INTEGRATION.md`。
- **代码导入：** 针对此目录的 `AssetPostprocessor` 配置 Humanoid；动画文件从对应角色复制 Avatar；动画保持原地，根运动烘焙到姿态；根据名称设置循环；提取材质供生成器重建 URP 材质。
- **动画选择由数据记录。** 表格将游戏动作映射到具体文件。`slash (2)` 等编号重复项通过动画姿态拼图选择。
- **回退：** Mixamo 目录不存在时，生成器使用已有的 CC0 Quaternius 骨架，让缺少授权资源的环境仍能够初始化、构建和测试。
- **控制器：** 生成的 Animator Controller 使用各角色独立动画集，覆盖启停移动、原地转向、锁定时横移、轻重攻击连招、格挡、招架、方向受击、眩晕、前后倒地、起身和死亡。

## 2. 重量感和移动

- **受击反馈：** 在上半身叠加层播放方向受击动画，保持未被打破的站姿。打击停顿随打击重量变化，镜头沿受击方向冲击；硬直和击杀附带短暂慢动作。
- **脚踏实地的移动：** Motor 速度驱动带加速和停止动画的混合；大幅改变方向时播放转身；站立时通过脚部 IK 固定脚掌，避免滑步。Boss 使用更沉重的节奏。
- **攻击：** 按每个动画自身的蓄势、接触和恢复阶段制作时序。攻击判定窗口始终是玩法依据，动画时间映射将接触帧对齐到该窗口。

## 3. 击倒和布娃娃

- 击飞、倒地和起身使用专用动画；根据打击方向相对身体朝向选择倒地动作。
- 死亡时从当前姿态和速度进入布娃娃，再由物理系统稳定下来，避免突然跳变。
- 起身等待身体实际停止运动。

## 4. 特效

- 肉体和护甲命中使用暗色血液、火花；地面使用石尘；重击使用余烬。
- 带纹理、逐渐淡出的刀刃拖尾。
- 砸地用裂纹贴花替换平面圆盘，地面预警改为微弱发光的裂缝。
- Boss 胸腔内部发光；Windows 档使用热浪扭曲。

## 5. 环境和 HUD

- 哥特式尖拱和肋拱替换方形门楣，增加碎石、旗帜、烛台、污垢和积水贴花，采用更暗、更暖的调色。
- 暗黑幻想 HUD：带边框的生命和体力条、Boss 名牌、统一风格的失败界面。

## 6. 验证

每个阶段都用视觉证据和测试共同判断：

- Windows 构建在相同固定时刻的前后对比截图。
- 采样帧序列合成为 GIF，直接评估运动表现。
- 检查性能预算：Windows p95 ≤ 8.3 ms、Draw Call ≤ 600；WebGL Draw Call ≤ 250。
- 所有 EditMode / PlayMode 测试通过，程序集依赖边界保持完整。

## 保持不变的规则

Boss 不作弊。资源由代码生成。不调用 `UnityEngine.Random`。只能由 `TimeService` 写入 `Time.timeScale`。命中时机由攻击判定时间轴决定。
